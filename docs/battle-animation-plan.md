# 足し算忍者：ドット絵戦闘演出の計画

作成日：2026-10-03

本体の学習機能と画面が仕上がった後に追加する演出の仕様。ユーザーとの相談で決まった内容と、任された項目の推奨仕様をまとめる。2026-10-03に初版の実装と素材制作を開始した。実装状況・素材形式・検証結果は [battle-animation-implementation.md](battle-animation-implementation.md) を参照。

## 目的と基本ルール

- 計算への回答が、忍者の戦闘として見える楽しさを加える。
- 戦闘は見た目の演出。学習の採点、制限時間、報酬、既存のレイドへのダメージ計算を変更しない。
- 回答中は構えと呼吸程度の待機。正解で攻撃、誤答で被弾する。
- 自キャラにゲーム上のHPや敗北条件は設けない。
- 通常コースは１コースで１体の大きな敵に勝利。誤答があっても最後まで取り組めば勝利する。
- 敵のHPは演出用の学習進行表示。既存の問題進行に合わせて減らし、誤答によって進行を戻さない。同じ問題への再入力で重複して進めない。
- コースの問題数が変わっても、開始時の敵HPを100%、正常終了時を0%として扱う。途中で終了した場合は勝利を付けない。

## 配置と表示条件

- 横長画面だけで表示する。スマホ縦画面には表示しない。
- 左端に小さめの自キャラ、右端に大きめの敵。向かい合う配置。
- ドット絵の風景は足元と両端だけ。中央の問題、回答、手書き、操作ボタンの読みやすさと大きさを保つ。
- 横長でも安全な余白が足りない場合は演出を隠す。実画面で寸法を確認し、表示可能な幅と高さを決める。
- ヒントを実際に開いている間は戦闘全体を隠す。ヒントを閉じると、現在の進行状態で待機姿に戻す。非表示中の攻撃をまとめて再生しない。
- 戦闘レイヤーは入力を遮らない。装飾として扱い、読み上げ対象にしない。

## 回答とアニメーション

- 正解：通常の斬撃。３連続以上の正解で手裏剣、５連続以上で分身攻撃。
- 誤答：敵の攻撃と自キャラの短い被弾動作。流血表現は使わない。連続正解の技段階だけをリセットし、敵を倒す進行は戻さない。
- 次の問題への移行、入力受付、神速のタイマーは演出を待たせない。
- 速い回答が続く場合、古い演出を長い待ち列にしない。最新の反応に切り替え、最後の勝利・撤退を優先する。
- 攻撃は両端からの短い動作やエフェクトで表現する。式や回答欄の上をキャラが横切る演出は避ける。
- 通常終了：最後の一撃、敵の消滅、刀を納める勝利姿を１〜２秒で見せて結果画面へ。タップでスキップ可能にする。オフ時は演出待ちを設けない。
- 神速・無限の記録挑戦が途切れた場合：煙玉で撤退し、結果に倒した敵の数を添える。結果画面の主役は既存の学習記録とする。
- 神速で所定のコースを正常に完走した場合は勝利。途中離脱はクリアとして扱わず、終了の既存ルールを維持する。

## 敵・場所とモードの組み合わせ

学習区分で敵と場所を決め、コース種別で戦い方を変える。すべての組み合わせに別のスプライトシートを作るのではなく、共通素材と技・色・背景の組み合わせで個性を付ける。

| 学習区分 | 敵の候補 | 場所 |
| --- | --- | --- |
| 基礎の数える練習など | 木人、からくり人形 | 道場 |
| くりあがりなし | 敵忍者、鎧武者 | 竹林、城門 |
| くりあがりあり | 鬼、天狗、大蛇、上級の龍 | 山、妖怪の森 |
| ばらばら | 各区分の敵 | 敵に対応した場所 |

| コース種別 | 戦闘の個性 |
| --- | --- |
| 通常（20問・ぜんぶ・にがて） | １コースで１体に勝利 |
| コツ | 師範・修行相手との組手。最後に相手がうなずき、修行達成を認める。進行と被弾の基本ルールは共通 |
| 神速 | 素早い斬撃と残像。入力とタイマーの進行を優先 |
| 無限 | 雑魚を倒し、節目にボス。終了時は煙玉で撤退 |

- 同じコースでも、その区分の敵候補から毎回選ぶ。可能なら直前と同じ敵を避ける。
- 基礎は別の練習画面もあるため、各画面の終了・正誤判定に合わせて接続方法を確認する。誤答のない課題に新しい誤答判定を追加しない。
- レイド接続中も、この敵HPは学習進行の演出用とする。実際のレイドボスのHPとは表示上区別し、レイド機能の仕様変更は別途扱う。

## 無限の推奨進行

20問を１周期とする。問題が既存ルールで次へ進んだ回数を用い、同じ問題への再入力は数えない。

- １〜５問：雑魚１体目。
- ６〜10問：雑魚２体目。
- 11〜15問：雑魚３体目。
- 16〜20問：ボス。20問目で撃破。
- 21問目から次の周期。敵・場所・演出の見た目を変え、学習の難度は既存設定のままにする。
- 各相手の規定問題数を完了した時点で撃破数を１増やす。途中の相手は撃破数に含めない。

## 自キャラと素材

- スーパーファミコン風のかっこいいドット絵。現在の `img/ninja_1.png`〜`ninja_4.png` を制作時に確認し、衣装、色、装備、シルエットの特徴を引き継ぐ。
- 既存の忍者成長段階に対応して姿を変える。成長に応じて刀、構え、攻撃エフェクト、分身、オーラにも差を付ける。
- 最初は成長段階ごとの基本キャラを完成させる。買い物で入手した装備の見た目反映は後続の拡張とし、対応できる刀・装備から追加する。
- 共通の待機、斬撃、手裏剣、分身攻撃、被弾、勝利、撤退を用意する。敵は待機、攻撃、被弾、撃破、修行達成に必要な動作を用意する。
- 自キャラと敵は別の透過スプライトシート。フレームの大きさ、足元の基準点、色数、ドット密度をそろえる。技のエフェクトは再利用できる別素材にする。
- 実際の解像度とフレーム数は、１組の試作を実画面に置いて決める。整数倍率を基本に拡大し、輪郭をぼかさない。

## 設定

| 設定 | 内容 |
| --- | --- |
| 通常（初期設定） | 呼吸・待機動作、回答時の攻撃、成長に応じたオーラ |
| ひかえめ | 常時動作・オーラを止め、回答時だけ短く動く。強い点滅や画面揺れを使わない |
| オフ | キャラ、風景、戦闘演出を表示しない |

設定は保存する。ヒント表示、画面の向き変更、コース終了、画面離脱で演出を正しく停止・復帰させる。追加の戦闘音は初版では設けず、既存の回答音との相性を見て後から判断する。

## 実装する順序

1. 本体の回答・手書き・ヒント・時間制限・結果表示と主要な横長画面での配置が安定した段階で着手する。
2. 忍者１段階、敵忍者１体、竹林の足元背景を試作し、「くりあがりなし・通常20問」でサイズと雰囲気を確認する。
3. 待機・攻撃・被弾・勝利、進行用HP、非同期の演出、設定、ヒント時の非表示を完成させる。
4. 忍者の全成長段階と連続正解の技を追加する。
5. 敵・場所の種類を増やし、コツ・神速・無限へ展開する。
6. 基礎の各画面へ対応し、その後に装備の見た目反映を検討する。

## 実装時に確認すること

- 横長のPC・タブレットで、回答方法ごとの操作領域と敵が重ならないこと。余白不足・縦画面では非表示になること。
- ヒント開閉で戦闘が消え、閉じた後に現在の状態へ戻ること。
- 連続回答しても入力を妨げず、演出がたまらないこと。神速の制限時間が変わらないこと。
- 誤答、再入力、コースの長さ変更でHP・撃破数が重複加算されないこと。
- 通常完走の勝利、神速・無限の撤退、途中離脱が区別されること。
- 設定の保存、演出オフ、成長段階の対応、画像読み込み失敗時にも学習が続けられること。
- 戦闘の追加で採点、学習記録、報酬、レイドへの送信が変わらないこと。
